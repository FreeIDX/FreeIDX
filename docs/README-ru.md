**Бесплатный современный форум с открытым исходным кодом, целиком построенный на Cloudflare.**

`Cloudflare Workers` · `React 19` · `Tailwind CSS 4` · `Hono` · `TypeScript` · `D1` · `KV` · `R2` · `i18n` · `AGPL-3.0`

[Возможности](#-возможности) · [Архитектура](#️-архитектура) · [Быстрый старт](#-быстрый-старт) · [Собственный домен](#-настройка-собственного-домена) · [Структура репозитория](#-структура-репозитория)

***

Форум на базе Cloudflare Workers + D1 + KV + R2 с поддержкой постов, комментариев, загрузки вложений, платного членства, SEO-индексации, мультиязычности и многого другого.

**💡 Работает полностью бесплатно**: фронтенд и бэкенд развёртываются как единый Worker-проект, статические файлы отдаются через Workers Assets, а D1/KV/R2 остаются в рамках бесплатного тарифа — нулевая стоимость, нулевое обслуживание.

***

## 🏗️ Архитектура

### Совмещённое развёртывание в одном Worker

```
User visits: forum.example.com
         ↓
   Cloudflare Worker「freeidx-api」(Edge network)
         ↓
  ┌─ Worker route matching
  │
  ├─ /assets/* ?
  │  └─ YES → Workers Assets serves static files directly (no Worker request consumed)
  │
  ├─ /api/* / /files/* ?
  │  ├─ YES → Hono Worker handles business logic
  │  │         ├ JWT + Session dual-track authentication
  │  │         ├ Permission engine (user groups × sections × moderators)
  │  │         └ Returns JSON / streams R2 files via proxy
  │
  └─ Others → Crawler pre-rendered HTML / SPA index.html, handled by React Router
```

### Технологический стек

| Слой                | Технологии                                                                         |
| ------------------ | ---------------------------------------------------------------------------------- |
| Фронтенд           | React 19 + React Router 7 + Tailwind CSS 4 + TanStack Query + Zustand + Vite       |
| Бэкенд             | Hono + TypeScript + Zod (Cloudflare Workers)                                       |
| База данных        | D1 (SQLite), KV для кеширования нечастых записей, Cache API для edge-кеширования   |
| Хранилище          | R2 (вложения/аватары, отдаются потоком через Worker-прокси `/files/:key`)          |
| Аутентификация     | JWT (httpOnly Cookie) + таблица сессий в D1, PBKDF2-SHA256                         |
| CAPTCHA            | Cloudflare Turnstile                                                               |
| Плановые задачи    | Cron Triggers (5-минутный уровень + ежечасный уровень сверки + ежедневный уровень) |
| Управление пакетами | pnpm workspace + Turborepo (monorepo: `apps/web` / `apps/api` / `packages/shared`) |

## ✨ Возможности

### 📝 Ядро форума

- ✅ **Управление постами** - Публикация, редактирование, удаление, закрепление, закрытие, перенос между разделами, выделение; пагинация на курсорах + бесконечная прокрутка; оптимистичные обновления TanStack Query (счётчики постов и просмотров обновляются мгновенно)
- ✅ **Система комментариев** - Ответы, цитирование, подсветка ключевых слов, отметки о прочтении, многоуровневые ответы
- ✅ **Загрузка вложений** - Изображения/файлы загружаются напрямую в R2 и отдаются потоком через Worker-прокси `/files/:key` — нулевая плата за исходящий трафик и обход квот на операции Storage Class B; встроенный **TipTap rich text editor** с вставкой кода и загрузкой изображений из буфера обмена
- ✅ **Поиск** - Поиск по ключевым словам внутри разделов с подсветкой найденных фрагментов

### 👥 Пользователи и права доступа

- ✅ **Аутентификация пользователей** - Регистрация, вход, выход, коды подтверждения по email, восстановление пароля; двухконтурная аутентификация JWT (httpOnly Cookie) + таблица сессий, защита от CSRF по всему сайту
- ✅ **Трёхуровневая система прав** - Группы пользователей × доступ к разделам × движок правил модераторов, с авторизацией на чтение/запись и модерацию вплоть до отдельного раздела
- ✅ **Автоматическое повышение групп пользователей** - Количество постов + тем, попадающее в кредитный диапазон, автоматически меняет группу — вручную вмешиваться не нужно
- ✅ **Центр пользователя** - Загрузка аватара, редактирование профиля, смена пароля, мои темы/ответы, настройки email-уведомлений
- ✅ **Действия модерации** - Закрепление/закрытие/удаление/перенос, удаление пользователя, поддержка пакетной обработки

### 💎 Членство и монетизация

- ✅ **Система членства** - Кредиты + уровни + VIP + платные вложения + оплата заказов, полный замкнутый цикл
- ✅ **Подключаемые платёжные каналы** - card / paypal / stripe / alipay, по одному независимому плагину на канал; payment-core содержит только контракты + реестр + конечный автомат заказов; включение/отключение каналов и ротация ключей из админ-панели без развёртывания
- ✅ **Рекламная система** - Пользовательские рекламные блоки + Google AdSense, гибкая настройка нескольких мест размещения

### 🔌 Расширяемость и инженерия

- ✅ **Механизм плагинов** - Точки расширения hook / overwrite + слоты фронтенд-компонентов, «горячая» замена из админ-панели, расширение функциональности без правки кода ядра
- ✅ **Админ-панель** - Настройки сайта, разделы, темы, пользователи, группы пользователей, кеш — всё в одном месте
- ✅ **Мультиязычность** - Упрощённый/традиционный китайский / английский / японский / корейский / французский / немецкий / испанский / русский / тайский — всего 10 языков, генерация скриптами + сквозная валидация на pre-commit, никакого захардкоженного текста
- ✅ **Плановые задачи** - Трёхуровневое расписание Cron Triggers (каждые 5 минут / ежечасная сверка / ежедневно), автоматизирующее очистку сессий, ежедневный сброс статистики, GC вложений и сверку «осиротевших» заказов

### 🔍 SEO / GEO индексация

- ✅ **Пре-рендеринг для краулеров** - SEO HTML генерируется заранее при записи и хранится в R2 + Cache API, отдаётся только user agent'ам краулеров; затраты CPU на рендеринг во время запроса структурно сведены к нулю
- ✅ **Полный набор для индексации** - sitemap, структурированные данные JSON-LD, llms.txt, политики для AI-краулеров, robots; псевдостатические URL `.htm` для обратной совместимости
- ✅ **Edge-кеширование** - Барьер чтения через Cache API; популярные эндпоинты получают `x-edge-cache: HIT` при втором обращении, заметно экономя квоту чтения D1

### 🔐 Безопасность и адаптация к бесплатному тарифу

- ✅ **Безопасность паролей** - PBKDF2-SHA256 (WebCrypto), количество итераций подобрано под лимит CPU Workers в 10 мс, с ленивым обновлением для совместимости со старыми хешами
- ✅ **CAPTCHA** - Интегрирована Cloudflare Turnstile, подключена на вход/регистрацию/создание постов/ответы/восстановление пароля
- ✅ **Почтовый сервис** - Пул аккаунтов SMTP / Email Provider для надёжной доставки писем с подтверждением и восстановления пароля
- ✅ **Глубокая адаптация к бесплатному тарифу** - Многоуровневое кеширование (LRU-память внутри Isolate + KV + кеш-таблица D1 + Cache API), объединённые запросы `DB.batch()`, асинхронный агрегированный подсчёт через `waitUntil` — выжимаем максимум из квоты 100k запросов/день, 5M чтений строк / 100k записей строк

## 🚀 Быстрый старт

## Способ 1: автоматическое развёртывание через GitHub Actions (рекомендуется)

В проекте есть `.github/workflows/deploy.yml`; пуш в ветку `main` или ручной запуск автоматически собирают и развёртывают проект в Cloudflare. D1 / KV пайплайн **сам находит по имени и создаёт при отсутствии** — файлы репозитория вручную править не нужно.

#### Шаг 1: получите Cloudflare API Token

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/)
2. Перейдите в **My Profile > API Tokens**, нажмите **Create Token**

   ![](images/img-01.png)
3. Нажмите "View all templates", выберите шаблон **Developer Services** на странице карточек шаблонов, всё остальное оставьте без изменений и нажмите **Review Token** для завершения.
4. Скопируйте Token (показывается только один раз) и Account ID вашего аккаунта, сохраните оба значения.

#### Шаг 2: настройте GitHub Secrets

Сделайте форк проекта в свой репозиторий. В вашем GitHub-репозитории:

1. Перейдите в **Settings > Secrets and variables > Actions**
2. Добавьте следующие секреты, для поиска нужного пункта ориентируйтесь на изображение ниже:

   ① **Settings** → ② **Secrets and variables → Actions** → ③ вкладка **Secrets** → ④ **New repository secret**.

   ![](images/img-02.png)

| Название секрета        | Значение                   | Описание                                        | Обязательно |
| ----------------------- | -------------------------- | ----------------------------------------------- | ----------- |
| `CLOUDFLARE_API_TOKEN`  | Cloudflare API Token       | Token, созданный на шаге 1                      | Да          |
| `CLOUDFLARE_ACCOUNT_ID` | Ваш Cloudflare Account ID  | Правая боковая панель главной страницы аккаунта | Да          |

**Переменные:**

| Название переменной | Значение                      | Описание                                                                                                                                                                                                                                                                             | Обязательно |
| ------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- |
| `SITE_URL`          | URL сайта                     | напр. `https://forum.example.com` (если домена пока нет, **не создавайте эту переменную сейчас**; вернитесь к этому шагу после привязки домена; не вводите слово "empty")                                                                                                             | Нет         |
| `TURNSTILE_SITEKEY` | Cloudflare Turnstile Site Key | [Cloudflare Turnstile](https://dash.cloudflare.com/?to=/:account/turnstile); без него виджет проверки не отрисуется на фронтенде. Изменение значения требует повторного развёртывания фронтенда, чтобы вступить в силу                                                                 | Нет         |

### Шаг 3: первое развёртывание

На странице **Actions** вашего GitHub-репозитория:

1. Выберите workflow **Deploy to Cloudflare**
2. Нажмите **Run workflow**, выберите ветку `main` и отметьте:
   - `apply_migrations` — создать таблицы (`apps/api/migrations/`)
   - `run_seed` — начальные разделы + первый администратор
3. Когда запуск завершится зелёным статусом, форум уже работает; Worker `freeidx-api` также создаётся только на этом шаге. **При последующих пушах в main эти две галочки по умолчанию выключены** и базу данных не затрагивают.

#### Шаг 4: настройте секреты среды выполнения

После того как первое развёртывание завершится зелёным статусом, `freeidx-api` появится в списке Workers. Откройте его → **Settings → Variables and secrets**, выберите тип **Secret** и добавьте их по одному (после сохранения значения не видны, но не перезаписываются при развёртываниях; заполняются один раз и действуют постоянно):

| Название             | Назначение                                                                      | Обязательно                                        |
| -------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------- |
| `JWT_SECRET`         | Подпись токена входа / CSRF                                                     | Да                                                 |
| `TURNSTILE_SECRET`   | Серверная проверка CAPTCHA (должен использоваться в паре с `TURNSTILE_SITEKEY`) | Нет                                                |
| `SECRETS_MASTER_KEY` | Мастер-ключ AES-GCM для платёжных секретов плагинов                             | Нет                                                |

Сгенерируйте случайное значение локально и вставляйте по одному:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Способ 2: локальная разработка

```bash
pnpm install

# Build the frontend first, then start the backend (wrangler dev reads the same [assets] config)
pnpm --filter @freeidx/web build
pnpm --filter @freeidx/api dev
```

- Локально используется miniflare; реальные ID ресурсов не нужны
- Секреты разместите в `apps/api/.dev.vars`
- База данных: `pnpm db:apply` — применить миграции, `pnpm db:seed` — загрузить начальные данные

## Способ 3: визуальная сборка через Cloudflare Dashboard

Workers & Pages → Create → **Continue with GitHub** тоже работает, но требует вручную вписать реальные ID D1/KV и `SITE_URL` в `apps/api/wrangler.toml` через веб-интерфейс GitHub (в репозитории лежат значения-заглушки; без замены сборка гарантированно упадёт), а имя проекта должно быть `freeidx-api`. Используйте либо этот способ, либо пайплайн.

## 🌐 Настройка собственного домена

1. Главная страница Cloudflare → **Add a domain**, подключите домен к Cloudflare и смените две NS-записи у вашего регистратора
2. Workers → `freeidx-api` → **Settings → Domains & Routes → Add → Custom domain**
3. Вернитесь в GitHub Variables и задайте для `SITE_URL` этот домен; запушьте любой коммит, чтобы изменения вступили в силу

Настройка Route не нужна — `/api/*`, `/files/*` и пути страниц находятся в одном Worker. Edge-кеширование включается автоматически после привязки собственного домена; также не забудьте отключить превью-домен `*.workers.dev`, чтобы поисковые системы не индексировали его как дублирующийся контент.

**Аккаунт администратора по умолчанию** (сразу смените его после первого входа!):

- Email: `admin@admin.com` / Пароль: `1`
